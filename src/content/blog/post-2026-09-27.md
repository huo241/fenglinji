## 1. adb 连接与设备识别

工具下载：Google 官方 platform-tools 直链（macOS）：

```
https://dl.google.com/android/repository/platform-tools-latest-darwin.zip
```

解压即用，无需安装。首次连接要点：

1. 手机开启开发者模式（连点版本号 7 次）→ 开启「USB 调试」
2. ColorOS 开启 USB 调试**强制要求登录 OPPO 账号验证**，绕不过去
3. USB 用途必须从「仅充电」切到「传输文件」，否则 Mac 看不见设备
4. 手机弹「允许 USB 调试吗」时勾选「一律允许」

验证：

```bash
adb devices -l        # 状态应为 device，而非 unauthorized / offline
adb shell getprop ro.product.marketname   # 机型
adb shell getprop ro.build.version.oplusrom  # ColorOS 版本
```

系统信息速查三件套：

```bash
adb shell dumpsys battery          # 电量/温度/充电状态
adb shell df -h /storage/emulated  # 存储占用
adb shell pm list packages -3 | wc -l   # 第三方应用数
```

## 2. ColorOS 16 的三层墙与绕过

### 2.1 墙之一：pm uninstall 被拦

对系统关键应用执行 `pm uninstall --user 0 <pkg>` 返回 `DELETE_FAILED_INTERNAL_ERROR`。
更阴的是 `pm disable-user` 会**假成功**——命令返回正常，实际 `dumpsys package` 里 `enabled=0`（默认启用），状态纹丝未动。验证要用 dumpsys，不能信命令返回值。

### 2.2 真相：开关不存在

社区流传的解法是开启开发者选项里的「USB 调试（安全设置）」。实测结论：

- ColorOS 16 **中文界面隐藏了开发者选项的部分开关**（系统语言切 English 后 "Disable permission monitoring" 等会现形）
- 但「USB 调试（安全设置）」在国行固件里被**整个删除**——遍历 global/secure/system 三个 settings 表均无对应存储键。找不到不是眼瞎，是 OPPO 删的

```bash
adb shell settings list global | grep -iE "关键词"
adb shell settings list secure | grep -iE "关键词"
adb shell settings list system  | grep -iE "关键词"
```

这三个命令是排查「某功能有没有开关」的通用手段。

### 2.3 突破口：pm suspend

`pm uninstall`、`pm disable-user`、`pm hide` 全被拦，但 **`pm suspend` 未被门禁覆盖**：

```bash
adb shell pm suspend com.opos.ads          # 冻结
adb shell pm unsuspend com.opos.ads        # 解冻
adb shell dumpsys package com.opos.ads | grep suspended   # 核验
```

挂起效果：图标变灰、无法启动、后台不运行、推送停止。实战效果九成等同卸载，且完全可逆。代价：系统 OTA 大版本更新后可能被自动解冻。

**包名情报**（实测定位）：

| 应用 | 包名 | 备注 |
|---|---|---|
| 广告服务 | com.opos.ads | 可冻结 |
| 系统浏览器 | com.heytap.browser | 冻结前确认有替代浏览器 |
| 软件商店 | com.heytap.market | 冻结后无法更新应用，需临时解冻 |
| 游戏空间 | com.oplus.games | 桌面游戏图标的真实宿主 |
| 游戏中心 | com.nearme.gamecenter | 主空间(user 0)未装，只存在于隐藏辅助用户(user 10)，需 `pm suspend --user 10` |
| 本地应用扫描引擎 | com.oplus.pscanvas | 安装检测的计算方 |

注意 `com.oppo.store` 是 OPPO 官方商城（卖手机的），别误伤；`com.android.adservices.api` 是安卓系统级 Privacy Sandbox，别碰。

排查包名的通用姿势：

```bash
adb shell pm list packages | grep -iE "关键词1|关键词2"
adb shell dumpsys window windows | grep -E "Window #|mActivityComponent="
```

### 2.4 「敏感权限」安装弹窗的解剖

安装 APK 时的「涉及敏感权限」页来自**安装器本体 `com.oplus.appdetail`** 的静态权限分析（读 APK 权限清单→敏感权限强制插页），纯本地、无开关、无「不再提醒」，焊死在流程里。能关掉的周边：

```bash
adb shell settings put global oplus_customize_apk_prescan_switch 0  # 安装前扫描
adb shell settings put global verifier_verify_adb_installs 0        # adb 安装校验
adb shell settings put global upload_apk_enable 0                   # APK 信息云端上传
```

**真正的绕路：adb install 完全绕过安装器界面**，弹窗根本不出现。

## 3. F-Droid 国内镜像（重要情报）

- **官方源 f-droid.org 被墙**：文字走缓存能加载，图标逐张拉取全裂
- **上海交大镜像 mirror.sjtu.edu.cn/f-droid/repo 已下线（404）**——网上教程多为过时信息
- **清华 TUNA 镜像可用**：`https://mirrors.tuna.tsinghua.edu.cn/fdroid/repo`

镜像可用性验证（索引文件约 61MB，200 即活）：

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  "https://mirrors.tuna.tsinghua.edu.cn/fdroid/repo/index-v2.json"
```

**添加镜像的最省事方法**：不用在 F-Droid 界面里找按钮（藏得深），直接推送带官方指纹的专用协议链接，F-Droid 会自动弹「这是官方仓库的镜像，是否添加」：

```bash
adb shell am start -a android.intent.action.VIEW -d \
  "fdroidrepos://mirrors.tuna.tsinghua.edu.cn/fdroid/repo?Fingerprint=43238D512CAA1E2B67D53E43BAEA179D6F509CDE9A2AF5D3736E90ABCB0E3837"
```

两个坑：
1. **必须用 `fdroidrepos://` 协议**，https 链接会被浏览器截胡
2. SJTU 已 404 时 F-Droid 报「无效的仓库」，先 curl 验证镜像活着再推

## 4. adb 直装 APK 全流程（含校验）

从镜像仓库装应用的标准流程，以 Organic Maps 为例：

```bash
# 1. 从 index-v2.json 解析最新版本号、文件名、官方 sha256
python3 -c "import json; d=json.load(open('idx.json')); ..."

# 2. 下载
curl -sL "https://mirrors.tuna.tsinghua.edu.cn/fdroid/repo/app.organicmaps_26082718.apk" -o app.apk

# 3. 哈希比对（必须 MATCH）
shasum -a 256 app.apk

# 4. 直装（绕过安装器 UI 及其弹窗）
adb install app.apk    # 成功输出: Performing Streamed Install / Success
```

当日经此流程安装：Fossify Calendar、Breezy Weather、Organic Maps，全部哈希校验通过。

## 5. 第三方启动器（Kvaesitso）与 ColorOS 的 Home 键之争

### 5.1 系统层设置会「阳奉阴违」

```bash
adb shell cmd role get-role-holders android.app.role.HOME
# 显示 Kvaesitso 已是默认桌面

adb shell cmd package set-home-activity de.mm20.launcher2.release
# 返回 Success，但按 Home 仍落回 com.android.launcher
```

结论：ColorOS 在框架层劫持 Home 键分发，命令层改数据**它不认**。可靠解法：在系统设置界面（设置→应用→默认应用→主屏幕应用）**人工切换一次**（先切走再切回），触发 ColorOS 自家绑定逻辑。

**重要的坑：`adb shell am force-stop` 启动器会把 Home 绑定抖回 ColorOS 桌面。** 修复：

```bash
adb shell cmd package set-home-activity de.mm20.launcher2.release
```

### 5.2 图标全黑块的原因

Kvaesitso 设置里「**强制应用主题**」（强制单色着色）开着时，ColorOS 私货图标格式经单色蒙版渲染只剩黑块。**关掉该开关**即恢复。这与「第三方启动器解析 OPPO 私货图标格式经常只拿到蒙版层」是同一类问题的两种表现。

### 5.3 Kvaesitso 天气服务商

新版 Kvaesitso 内置天气源只剩 Deutscher Wetterdienst（仅限德国），MET Norway/Open-Meteo 拆成外部对接。路径：设置 → 兼容方式 → 天气 → 服务商。解法是装 **Breezy Weather**（org.breezyweather，F-Droid 有）：

1. Breezy Weather 内添加位置（搜索走 GeoNames/Open-Meteo，中文输入不了可输拼音）
2. 数据源全默认 Open-Meteo（免注册、国内直连）
3. **force-stop Kvaesitso 再启动**，服务商列表才会出现 Breezy Weather 选项
4. 选定后桌面卡片刷新，链路打通

## 6. 调试手段备忘

### 6.1 远程「看」手机屏幕

```bash
adb exec-out screencap -p > screen.png     # 截屏拉回本机
adb shell uiautomator dump /sdcard/d.xml   # 抓 UI 树
adb shell cat /sdcard/d.xml | grep -oE 'text="[^"]+"'   # 提取全部文本
adb shell dumpsys window | grep mCurrentFocus          # 当前焦点窗口（判弹窗归属）
```

### 6.2 模拟操作

```bash
adb shell input tap x y            # 点击
adb shell input swipe x1 y1 x2 y2 时长ms   # 滑动
adb shell input keyevent KEYCODE_HOME / KEYCODE_BACK
adb shell input text "EnglishOnly"  # 不支持中文
adb shell am start -a android.intent.action.VIEW -d "URI"   # 推送链接
```

**坐标系坑**：uiautomator dump 的 bounds 是真实屏幕坐标，直接用；截图是缩略图（宽 512），换算比约 x×2.11 / y×2.22，**点按以 dump 坐标为准**，用截图坐标盲点必翻车。UI 树偶发缓存旧数据，点偏后要重新 dump 再取坐标。

### 6.3 蹲点监视弹窗

后台循环抓焦点窗口，复现瞬时弹窗归属：

```bash
for i in $(seq 1 45); do adb shell dumpsys window | grep mCurrentFocus; sleep 2; done
```

## 7. 环境坑位录

- **macOS 沙箱**：Bash 工具跑 adb 长复合命令触发 sandbox 报错，需关闭沙箱 + 单条短命令
- **zsh 语法陷阱**：`echo ===` 中的 `===` 被 zsh 的 `=cmd` 展开机制吃掉报错，分隔符别用等号
- **中文输入**：`adb shell input text` 不支持非 ASCII，搜索框输入用拼音
- **应用确认**：包名必须 `pm list packages` 实查，近亲包名瞎猜必出事（如 oppo.store ≠ heytap.market）

## 8. 附：打印机双面的硬件判别法

Mac 端 CUPS 一条命令列出打印机全部可设选项：

```bash
lpoptions -p "打印机名" -l
```

输出里**没有 Duplex 项 = 硬件没有自动双面器**，任何软件（包括 HP 自家 App 的繁琐双面流程）都是手动双面的包装。此时最优解是 macOS 打印对话框自带的「纸张处理 → 仅奇数页 / 仅偶数页」两趟出纸法，免倒腾塞纸。

## 一图流总结

```
adb 连接 → 实查包名 → pm suspend 冻结（绕三层墙）
                    ↘ settings put 关上传/扫描
F-Droid → TUNA 镜像（fdroidrepos:// + 指纹）
        ↘ index-v2 解析 → 下载 → sha256 校验 → adb install
Kvaesitso → 界面人工绑定 Home（命令无效）→ 关强制主题
天气 → Breezy Weather + Open-Meteo → 强停重启识别
```

全部操作可逆：`pm unsuspend` 解冻、`cmd package set-home-activity` 回绑、settings put 改回 1。
